n.001 · Intent

왜 만들었나

코딩테스트는 기업마다 자주 나오는 유형과 평가 포인트가 다르다. 그런데 목표 없이 풀면 실제 시험에서 낯선 유형에 시간을 뺏긴다 — 그 문제 정의에서 출발했다.

풀지 못한 문제

  • 기업마다 출제 경향이 다른데 무작위로 문제를 풀며 시간을 낭비했다
  • "매일 한 문제씩" 다짐은 세우기 쉬워도 지키기 어려웠다
  • 기존 코테 사이트는 개인화된 정시 알림도, 기업별 문제 선별도 해주지 않았다

대신 만든 것

  • 기업 · 알고리즘 태그 · 난이도로 나만의 "오늘의 문제" 필터
  • 로그인 없이 익명 clientId 하나로 설정이 그대로 유지
  • 새 문제는 GitHub PR로 제안 → 검토 후 반영, 계속 채워지는 구조
의도적으로 범위 밖에 둔 것도 있다 — 로그인/계정, 자동 채점, PR 자동 병합, 통계 대시보드는 지금 버전에서 다루지 않는다. 문제 원문은 스크래핑하거나 iframe으로 끌어오지 않고, 핵심 포인트 · 풀이 접근을 항상 직접 작성해 저작권 문제를 피한다.
n.002 · System Flow

동작 흐름

서버는 늘 깨어있지 않다. 15분마다 깨워져 "지금 보낼 사람"을 판정하고, 문제 제안은 사람이 검토해야만 실제로 반영된다.

① 매일 알림이 도착하기까지

각 단계를 눌러보면 표시가 남는다.

01 GitHub Actions / cron-job.org15분마다 /api/send-daily 호출
02 Express 서버 판정요일 · 시각 · 일시정지 · 오늘 중복발송 여부 체크
03 오늘의 문제 계산기업/태그/난이도 필터 + 순차·랜덤·안 푼 우선
04 web-push 발송VAPID 키로 서명해 Push 서비스로 전달
05 기기에 알림 도착잠금화면 · 알림센터에 표시
06 알림 클릭 → 앱 진입서비스 워커가 앱으로 포커스 이동

위 판정 · 계산 단계는 전부 storage.js를 거쳐, Postgres(Neon) 또는 로컬 파일 폴백 위에서 똑같이 동작한다.

② 문제가 늘어나는 방법
01 문제 제안 폼완전 공개, 누구나 제출 가능
02 github-suggest.js브랜치 생성 → problems.json 커밋 → PR 생성
03 저장소 소유자 리뷰스팸·품질 확인, 자동 병합 없음
04 problems.json 갱신다음 배포부터 오늘의 문제 풀에 반영

n.005 · Group Feedback

발표하며 받은 질문들

그룹 발표 때 나온 질문과 그 자리에서, 또는 다음 버전에서 답한 내용이다.

Q
팀원 답변 접기 −
로그인도 없는데 사용자 설정이랑 풀이 기록은 어디에 저장돼요?
A
AlGoPing
브라우저에서 발급한 익명 clientId(UUID)를 localStorage에 저장하고, 서버가 Postgres subscribers 테이블(또는 로컬 파일)에 매핑해요. 계정이 없어도 설정이 유지되는 이유예요.
Q
팀원 답변 보기 +
문제 제안 폼이 완전 공개면 스팸이나 이상한 제안이 들어오지 않아요?
A
AlGoPing
제출되면 GitHub API로 브랜치·커밋·PR까지는 자동 생성되지만, problems.json에 실제로 반영되는 건 항상 제 리뷰 후 수동 병합이에요. 자동 병합은 의도적으로 범위 밖에 뒀어요.
Q
팀원 답변 보기 +
무료 서버(Render)인데 알림이 제 시간에 오나요?
A
AlGoPing
서버가 항상 깨어있지 않아서, GitHub Actions가 15분마다 깨워 발송 대상을 판정해요. 그래서 목표 시각 대비 최대 30분의 오차는 허용 범위로 잡아뒀어요.
Q
팀원 답변 보기 +
오늘의 문제 말고, 알고리즘 개념만 따로 훑어보는 화면도 있으면 좋겠어요.
A
AlGoPing
좋은 제안이라 반영했어요 — 문제 태그 기반 /api/algorithms를 만들고, 오늘의 문제·설정·풀이기록과 동급인 4번째 탭 "알고리즘"을 새로 추가했어요.
